# Premium SaaS explainer craft — research notes (2026-10-06)

## Ranked craft rules (testable where possible)
1. ONE IDEA PER SHOT, ONE FOCAL ELEMENT. Each shot = one VO sentence/clause = one hero element. Test: per shot, exactly 1 element at full contrast/scale; everything else <=40% opacity, desaturated or blurred. Shot length 2-5 s (100 s video -> ~20-35 shots/beats).
2. VO CARRIES THE WORDS, SCREEN CARRIES THE PICTURE (Mayer redundancy + modality principles). Never caption the narration. On-screen text only for: product name, a number/KPI, a short label, or a technical term. Test: <=6 words per text block, <=1 text block per shot, <=~12 words visible at any time; text never duplicates the VO sentence verbatim.
3. SIGNALING (Mayer): highlight what VO names, at the moment it names it — scale-up 1.05-1.1, accent colour (the single orange), underline/ring, dim the rest. Accent colour is reserved for "the thing that matters now" (<=10% of frame area).
4. TEMPORAL CONTIGUITY / VO SYNC: visual action starts ~2-6 frames (≈0.1-0.2 s) BEFORE the stressed keyword (eye leads ear); settle ≤ word end. Hold the result ≥0.5-1 s after VO stops on it. (Practitioner convention, not a formal standard — measure in corpus.)
5. NO COLLISIONS: layout on a grid (e.g. 12-col, safe margin ≥5% of frame width / title-safe 90%); every element has a reserved box; boxes never intersect except intentional stacking with shadow (z-depth). Max 3 depth layers (bg / card / pop-over). Test: bounding-box intersection check per frame.
6. NEGATIVE SPACE: hero occupies ~30-60% of frame; ≥35% empty. Light grey bg + white cards + navy type = depth by shadow, not borders.
7. CONTINUITY: never hard-cut between unrelated layouts. Use a persistent hero object (e.g. the Acme "answer card" or a brand dot) that morphs container->container (Material "container transform"), or shared-axis push (x/y/z) for sequential/hierarchical relations, or push-in/zoom-through into a UI element to go "deeper". The transition IS the explanation (e.g. a ChatGPT answer card zooms into the mention -> becomes a row in the Acme table). Match cuts: subject keeps same screen position and continues momentum across the cut (School of Motion).
8. STYLIZED UI, NOT SCREENSHOTS: rebuild UI as simplified vector components (remove nav chrome, 60-80% of copy replaced by grey skeleton bars, keep 1-3 real labels/numbers). Crop tight on the relevant component; scale UI 150-300% so text is legible at 1080p mobile. Float components as cards rather than full app windows.
9. CURSOR: optional, used only for causality ("click -> result"). Cursor travels on eased arcs (not linear), ~0.4-0.8 s per move, 2-4 frame press-squash on click, then result reacts. Never more than one cursor action per shot.
10. LOGOS/ICONS: real brand marks for third-party engines (ChatGPT/OpenAI, Gemini, Perplexity) as icons in uniform containers (same size circle/rounded square, same stroke), never typed names alone; obey each brand's clear space, never stretch/recolor/crop (OpenAI guidelines). Own icon system: one stroke weight, one corner radius, one grid (e.g. 24 px), line icons in circles (Ramp/Qualetics refs).
11. EASING: never linear for spatial moves. Entrances = decelerate (Carbon expressive entrance cubic-bezier(0,0,0.3,1); M3 emphasized decelerate (0.05,0.7,0.1,1)); exits = accelerate (Carbon (0.4,0.14,1,1); M3 (0.3,0,0.8,0.15)); on-screen moves = standard (Carbon expressive (0.4,0.14,0.3,1)). Exits faster than entrances (~70-80% duration).
12. DURATIONS: UI micro 150-250 ms; card entrances 400-700 ms; camera/scene transitions 600-1000 ms; scale duration with distance/size (Carbon: "duration dynamic based on size").
13. OFFSET & DELAY (stagger): related items enter 40-80 ms apart (2-5 frames @60), max ~6 items before grouping; total stagger ≤ ~400 ms. Parenting: children move with parent.
14. FOLLOW-THROUGH/OVERLAP: secondary elements settle 2-6 frames after the lead; one subtle overshoot (≤3-5% or spring with low bounce) on hero arrivals only — not on text.
15. HOLDS: every "result" state holds ≥1 s; scene ends with ~0.5 s of stillness before transition (gives eye time).
16. MUSIC RHYTHM: hits of major transitions on beats/downbeats (bar = 2 s at 120 bpm); micro anims free.
17. 2.5D/3D TASTEFULLY: tilt UI planes 10-25° in perspective for "overview/data" moments (Linear Insights: tilted 3D scatter), parallax 2-3 layers, soft shadows; keep text-bearing planes facing camera when they must be read.
18. TYPE-LED vs UI-LED: type-led for problem/claim/category statements (big, 1 line, ≤5 words, centered or left on grid); UI-led for "how it works"; alternate to set rhythm. Notion AI (2023) cropped huge UI type so the UI itself becomes the typography.

## Process (studio standard)
Brief -> script (VO ~130-150 wpm; 100 s ≈ 220-250 words) -> VO scratch/final (timing locked to audio) -> moodboard -> 2-4 STYLE FRAMES (must contain: palette usage incl. accent rule, type hierarchy (H1/label/number), UI component style, icon system + third-party logo treatment, background/depth treatment, one representative "hardest" frame e.g. busiest data scene) -> storyboard (one frame per shot with VO line, transition arrows, camera notes) -> animatic (boards timed to VO, rough transitions; approve pacing here) -> design all frames -> animation -> SFX/music -> mix. Client sign-off at each stage; animate only after animatic approval.
